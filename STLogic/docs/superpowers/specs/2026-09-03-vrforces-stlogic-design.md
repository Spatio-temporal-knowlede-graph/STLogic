# VR-Forces STLogic 실험 설계

> 메인 데이터셋을 백마고지(battlefield_hill395)에서 VR-Forces 시뮬레이션 산출물로
> 교체하면서, 방법론을 두 데이터 체제 모두에서 성립하도록 일반화한다.
> 작성: 2026-09-03. 관련: [PROGRESS.md](../../PROGRESS.md),
> [STLogic_연구내용.md](../../STLogic_연구내용.md),
> 변환기 스펙 `2026-07-16-battlefield-stkg-to-tlogic-converter-design.ko.md`.

## 0. 요약

백마고지에서 최고 성능을 낸 조합(① 공간 backoff 후보생성 · ② 타입조건부 σ ·
③ tie 게이팅 · ④ 부대 중심점)은 **VR-Forces 데이터에서 재현되지 않는다.** 두
데이터셋의 체제가 반대이기 때문이며, 이는 추정이 아니라 §1의 측정으로 확인했다.

따라서 이 문서는 세 가지를 정한다.

1. **데이터셋** — 현 VR-Forces GT는 link forecasting 벤치마크가 될 수 없다. 무학습
   베이스라인이 MRR 0.9904를 내고(§1.2), 유일하게 헤드룸이 있는 `Fire-Weapon`은
   고유 (사수,표적) 쌍이 4개뿐이며 타임라인 끝 6.3%에만 존재해 학습 구간
   인스턴스가 0개다(§1.5). **현재 쓸 수 있는 타겟 관계가 하나도 없다.** 타겟 관계
   증량이 실험의 전제조건이며, 증량은 LLM이 교전 방침만 쓰고 코드가 결정론적으로
   확장하며 사전등록 합격검사로 검증한다.
2. **방법** — ①②③을 **쿼리 단위 불확실성 적응 융합(λ)** 하나로 대체한다. 기존
   장치들이 이 식의 특수해로 흡수되고, 손으로 고른 하이퍼파라미터가 사라진다.
3. **실험** — 확장 유/무 두 열에서 모두 TLogic 대비 격차가 양수임을 보여
   "일반화된 방법론"을 입증한다.

## 1. 배경: 왜 백마고지 방법론을 그대로 옮길 수 없는가

### 1.1 두 데이터셋은 체제가 반대다

| | 백마고지 hill395 | VR-Forces GT |
|---|---|---|
| 장면 | 75개 섹터, 섹터별 네임스페이싱 → **완전 inductive** | **단일 전투 1개** → 시간 분할, transductive |
| 엔티티 | 5,876 | 328 (+통제점 15) |
| 관계 | 10종, 엣지 116,680 | 실질 6종, object 채워진 행 340,101 |
| 편중 | 비교적 고름 | `Follow-Entity`→`ENINF001` 하나가 131K/149K (88%) |
| 좌표 | 투영 미터, 희소 | 위경도, **1Hz 조밀 궤적** (관계 엣지가 아닌 행 686,281) |
| 부대 계층 | `partOf` 있음 | 원 CSV에 없음 (`config/orbat.json`은 별도) |
| 규칙 미발화 쿼리 | 27% (11,118건) | 0에 가까울 것으로 예상 |

마지막 행이 결정적이다. 백마고지 최대 성과였던 ① 공간 backoff는 "규칙이 발화하지
못한 쿼리"를 채우는 장치다. VR-Forces는 관계 종류가 적고 반복이 극심해 채울 빈칸이
없다. **+4.3%p의 주역이 무력화된다.**

반대로 백마고지에서 죽어 있던 재순위화는 여기서 살아날 여지가 있다. hill395의
`cosb`는 σ가 거의 균일해 노이즈였는데, 이는 궤적이 희소해 유한차분 속도 추정이
망가졌기 때문이다. VR-Forces는 1초 간격이라 Δd·β가 실제로 의미를 갖는다.

### 1.2 측정 1 — 현 데이터셋은 벤치마크가 될 수 없다

`build/stkg/ground_truth_ver1.0.csv` 기준, 학습을 전혀 하지 않는 "직전 object 반복"
베이스라인:

```
recency     MRR 0.9904   H@1 0.9865   H@10 0.9966
frequency   MRR 0.9904   H@1 0.9865   H@10 0.9966

관계별 후보공간 / MRR
  move to           140,503 엣지   object 11개   MRR 0.9938
  Follow-Entity     106,559 엣지   object  2개   MRR 1.0000
  FFE-on-Location     2,510 엣지   object  7개   MRR 1.0000
  Fire-Weapon           338 엣지   object  4개   MRR 0.5195
  find_cover              3 엣지   object  1개   —
```

TLogic도 0.99를 낼 것이고 STLogic이 이길 여지는 0.01뿐이다. 거기서 나오는 어떤
개선도 노이즈와 구별되지 않는다.

### 1.3 측정 2 — 유일한 헤드룸은 사격 관계에 있다

`Fire-Weapon` 사건 시점에 사수 기준 대립 진영 후보:

```
반경  500m : 후보 중앙값   2   실제 표적 포착 0/650   (표적은 전부 500m 밖)
반경 1000m : 후보 중앙값  36   최근접순 MRR 0.108
반경 2000m : 후보 중앙값 191   최근접순 MRR 0.108
```

사거리 안 적 36명 중 거리만으로 고르면 MRR 0.108이다. **여기는 천장이 아니라
바닥이며, 변별 여지가 실재한다.** 타겟 관계로 사격·교전을 택하는 근거다.

단, `Fire-Weapon` 650건은 **고유 (사수, 표적) 쌍이 단 4개**다. 사실 4개를 163번씩
반복 기록한 것이다.

### 1.4 측정 3 — 전환 전용 평가셋은 성립하지 않는다

"상태가 바뀌는 순간만 평가한다"는 우회로를 검토하고 기각했다.

```
고유 (subject, predicate) 계열 332개 중 object가 한 번도 안 바뀌는 것 301개 (90.7%)
전환 이벤트 총 157건 → test 16건
전환 전용 베이스라인: recency MRR 0.1682 / frequency MRR 0.4536  (n=16)
```

베이스라인은 의도대로 무너지지만 n=16이다. **이 데이터에는 숨어 있는 예측 문제가
없다.** 값싼 우회로는 존재하지 않으며, 어떤 형태로든 타겟 증량이 불가피하다.

### 1.5 측정 4 — 사격은 타임라인 끝 6%에만 존재한다

관계별 시간축 분포(고유 시각 1,325개, ts 0..1324):

| 관계 | 엣지 | ts 범위 | 범위 비율 | 80/10/10 분할 시 train / valid / test |
|---|---:|---|---:|---|
| `move to` | 140,503 | 12–1318 | 98.6% | 109,831 / 15,895 / 14,777 |
| `Follow-Entity` | 106,559 | 12–1318 | 98.6% | 77,292 / 14,916 / 14,351 |
| `FFE-on-Location` | 2,510 | 12–1318 | 98.6% | 1,992 / 264 / 254 |
| **`Fire-Weapon`** | **338** | **1234–1318** | **6.3%** | **0 / 0 / 338** |
| `find_cover` | 3 | 446–969 | 39.5% | 3 / 0 / 0 |

사격이 전투 클라이맥스에만 몰려 있다. 시간 분할에서 **학습 구간의 `Fire-Weapon`
인스턴스가 0개**이므로 TLogic은 이 관계를 head로 갖는 규칙을 학습할 수 없고, 모든
사격 쿼리가 규칙 미발화가 된다. 실험이 성립하지 않는다.

`FFE-on-Location`은 타임라인 전체에 퍼져 있으나 후보공간 7개에 베이스라인
MRR 1.0000으로 포화이고, `find_cover`는 총 3건이다. **현재 쓸 수 있는 타겟 관계가
하나도 없다.**

이 측정은 증량 요건에 **시간축 분산** 조건을 추가하게 만든다(§2.2, §2.4). 단일
전투 서사에서 교전이 특정 국면에 집중되는 것은 구조적 현상이므로, 방침 설계에서
명시적으로 다루지 않으면 증량 후에도 재발한다.

## 2. 데이터셋 구축 요건

### 2.1 관계의 역할 분리 — 순환논증 차단

확장 관계(`next_to`·`in_front_of`·`behind`·`in_range_of`·`approach`)는
[thresholds.py](../../../../VR-Forces/vtmak/spatial/thresholds.py)에서
**(위치, 헤딩, 타입)의 결정론적 함수**로 정의된다(`next_to` = 거리 < 타입별
최소이격 × 3, 방위 섹터 45°/135°, 무기 사거리, 500m 관심반경).

기하로 정의된 것을 기하로 맞히면 자명한 승리다. 따라서 역할을 분리한다.

| 역할 | 술어 | 처리 |
|---|---|---|
| **타겟**(평가) | `Fire-Weapon`, `damages`, 증량으로 생기는 교전 술어 | 쿼리 생성 대상 |
| 타겟 후보(보류) | `FFE-on-Location` | 후보공간 7개·베이스라인 MRR 1.0으로 포화. 별도 행 보고(§7) |
| 타겟 불가 | `fired_by` | GT 905행 전부 object 미확정(사수 판별 실패). 사용 불가 |
| **맥락**(입력) | `next_to`, `in_front_of`, `behind`, `in_range_of`, `approach` | 규칙 body 재료. 평가 제외 |
| **맥락**(입력) | `move to`, `Follow-Entity`, `Wait-Duration` | 규칙 body 재료. 평가 제외 |
| 포화 대조군 | `move to`, `Follow-Entity` | 별도 표에 제외 근거로 §1.2 수치 보고 |

`firesUpon`은 시나리오에서 오는 사실이다 — 누가 실제로 방아쇠를 당겼는가. 기하는
이를 **제약하지만 결정하지 않는다**(사거리 안 전방에 적 36명, 실제 사격은 한둘).
이것이 STLogic이 풀겠다고 주장한 문제 자체이며, 순환은 원천 차단된다.

`move to`·`Follow-Entity`는 버리지 않고 맥락으로 남긴다.
`Follow-Entity(X, ENINF001)`는 X가 지휘관을 따르는 제대라는 정보이고, 사격 표적
예측에 쓸 수 있는 실제 신호다.

**확장 유/무 비교가 공정해지는 이유**: 타겟 집합이 양쪽에서 동일하다. 확장한 쪽은
규칙 body에 쓸 술어가 늘 뿐이다. 같은 문제, 같은 정답, 같은 지표.

### 2.2 타겟 관계 증량 요건

세 조건을 **모두** 만족해야 한다. 행 수만 늘리는 것은 성공이 아니다.

| 요건 | 현재 | 목표 | 이유 |
|---|---|---|---|
| 고유 (사수, 표적) 쌍 | 4 | **≥ 300** | 4개면 test에 1~2개. 통계 불성립 |
| 고유 사수 수 | 4 | **≥ 60** | 특정 개체 과적합 방지 |
| **사수당 표적 수** | **1** | **≥ 3** | (가) 아래 |
| 타겟 엣지 총량 | 338 | **≥ 10,000** | test 10% ≈ 1,000 쿼리 |
| **타겟 엣지 ts 범위** | **6.3%** | **≥ 60%** | (나) 아래 |
| **train 구간 타겟 엣지** | **0** | **≥ 6,000** | (나) 아래 |

**(가) 사수당 표적 수**가 결정적이다. 한 사수가 시나리오 내내 같은 표적만 쏘면 엣지를 10만 개로
늘려도 "직전 표적 반복"이 다시 MRR 1.0을 낸다 — `Follow-Entity`(후보 2개,
MRR 1.0000)에서 실제로 벌어진 일이다. **같은 사수가 시간에 따라 다른 표적으로
전환해야 예측 문제가 존재한다.** 이 조건은 기존 상호작용 보강 스펙
(`2026-08-27-vr-forces-interaction-task-enrichment-design.md`)에 없으므로 추가한다.
전투 국면 전환(전방방어선 → 킬존 → 예비진지)에 표적 갱신을 걸면 자연스럽다.

**(나) 시간축 분산**은 §1.5에서 나왔다. 현 데이터의 사격은 마지막 6.3% 구간에만
있어 학습 구간 인스턴스가 0개다. 교전이 클라이맥스에 몰리는 것은 단일 전투 서사의
구조적 현상이므로, 방침이 **모든 국면에 교전을 배치**하도록 명시하지 않으면 증량
후에도 재발한다. 지속적 방어전에서 접촉이 전 국면에 걸쳐 일어나는 것은 군사적으로
자연스러우므로 서사를 훼손하지 않는다.

시간 분할이 국면 분할과 겹치므로 train과 test의 관계 혼합비가 달라지는 분포 이동이
남는다. 이는 forecasting에서 현실적인 조건이지만, 국면별 교전 활동량을 비슷하게
유지해 교란 요인을 줄인다.

### 2.3 증량 방식 — LLM은 행이 아니라 방침을 쓴다

LLM에게 "FRINF027은 누구를 쏘는가"를 직접 물으면 LLM은 위치·진영·사거리·정면
여부로 추론한다. **그것이 정확히 STLogic의 특징집합이다.** 정답이 기하의 함수가
되고 STLogic은 구조적으로 이긴다. 생성 단계에 숨은 순환이며 발견하기 어렵다.

역할을 다음과 같이 나눈다.

| 주체 | 결정하는 것 | 결정하지 않는 것 |
|---|---|---|
| **LLM** | 국면별 교전 방침 — "국면 3에서 1중대는 기갑 우선표적으로 전환", "박격포반은 킬존 제압 후 예비진지로 표적 이동" | 좌표, 시각, 구체적 개체 쌍 |
| **코드** | 실제 관측 궤적에서 방침을 만족하는 (사수, 표적, 시각) 선택 | — |
| **코드** | 물리 제약 강제 — 대립 진영 · 생존 · 사거리 내 · 시간 간격 · 중복 배정 금지 | — |

LLM 출력은 CSV 백만 행이 아니라 **방침 파일 한 개**다. git에 커밋되고, 확장은
결정론적이며, 리뷰어가 읽고 검증할 수 있다. 재현성 문제가 사라진다.

산출물은 `STKG/data/expansion_of_spatio-temporal_information/pre-made-input/`
규약을 따른다.

### 2.4 합격검사 (사전 등록)

증량 결과물은 아래를 통과해야 채택한다. 미달이면 배치를 폐기하고 방침을 고쳐
재생성한다. 순환 여부를 논쟁이 아니라 측정으로 만든다.

| 검사 | 기준 | 근거 |
|---|---|---|
| 최근접 적 베이스라인 MRR | **< 0.20** | 실데이터 실측이 0.108(§1.3). 크게 벗어나면 기하 밀수 |
| recency 베이스라인 MRR | **< 0.30** | 사수가 표적을 실제로 바꾼다는 증거 |
| 고유 (사수, 표적) 쌍 | **≥ 300** | §2.2 (가) |
| 사수당 평균 표적 수 | **≥ 3** | §2.2 (가) |
| 타겟 엣지 ts 범위 | **≥ 60%** | §2.2 (나) |
| train 구간 타겟 엣지 | **≥ 6,000** | §2.2 (나). 0이면 규칙 학습 자체가 불가 |
| valid·test 구간 타겟 엣지 | **각 ≥ 700** | 지표 분산 억제 |

백마고지도 자체 구축 데이터셋이었다. 합성이라는 것 자체는 흠이 아니다. 흠이 되는
것은 **정답이 특징의 함수인 경우**뿐이며, 위 검사는 그것만 겨냥한다.

### 2.5 변환기 `convert_vrforces.py`

사용 컬럼은 `subject, predicate, object, timestamp, latitude, longitude` 6개로
한정한다. 백마고지 변환기와 같은 5컬럼+좌표 포맷으로 내보낸다.

- **좌표 투영**: 위경도 → 장면 중심 기준 국소 ENU 미터. 21°N에서 경도 1°는 위도
  1°의 0.93배이므로, 투영 없이 Δd·cos β를 계산하면 방위가 왜곡된다. 백마고지는
  이미 투영 미터였으므로 없던 단계다.
- **타입 복원**: `entity_type` 컬럼을 쓰지 않으므로 이름 접두사에서 파싱
  (`FRINF`/`ENT72`/`ENCAESAR`/`FRMORT`/`FRSNP` …). 진영은 `FR`/`EN`에서 복원.
  타입 사전 없이 동작한다는 점이 일반성 주장에 유리하다.
- **ts id**: 1,325개 → 연속 rank id. 백마고지의 uint16 초과 버그는 재발하지 않는다.
- **관계 엣지가 아닌 행 686,281개** (`none` 676,976 + `Wait-Duration` 8,400 +
  object 미확정 `fired_by` 905): 엣지가 아니라 **궤적 기질(substrate)** 로만
  적재한다. TLogic은 이 행을 소비할 수 없고 STLogic만 쓸 수 있다 — 그 자체로
  구조적 차별점이다.

### 2.6 분할과 유출 차단

- **메인**: 시각 기준 80/10/10 시간 분할 (표준 forecasting 설정, transductive).
- **보조**: 아군(FR) 주체 학습 → 적군(EN) 주체 예측 (inductive 전이 주장).
- **유출 차단**: `PositionIndex`가 쿼리 시각 **미만**만 보도록 제한한다. 현재
  구현은 at-or-before라 쿼리 시각 좌표를 읽는다. 타겟이 시나리오 유래 사실이라
  §2.1 구조에서 치명적이지는 않으나, 명시적으로 닫고 회귀 테스트로 고정한다.

## 3. 방법: 불확실성 적응 공간 융합

### 3.1 쿼리 단위 시간 불확실성 λ

쿼리 `q = (s, r, ?, t)`에 대해 TLogic이 후보집합 `C`와 점수 `S_T(c)`를 낸다.
확률로 정규화한 뒤 정규화 엔트로피를 λ로 쓴다.

```
p(c) = S_T(c) / Σ S_T          λ(q) = H(p) / log|C|

|C| = 0  →  λ = 1     (시간 규칙이 아무 말도 못 함)
|C| = 1  →  λ = 0     (시간 규칙이 단정함)
```

### 3.2 결합

```
S(c) = S_T(c)^(1−λ) · S_S(c)^λ
```

로그선형 결합이며 λ가 두 근거의 신뢰 지수가 된다. λ=1이면 식은 `S(c) = S_S(c)`,
곧 후보 풀을 공간 적합도로 순위화하는 것이 되는데 그것이 정확히 백마고지의
① backoff다. 백마고지에서 backoff는 `--backoff` 플래그로 붙인 별도 코드 경로였으나
여기서는 **수식의 특수해로 흡수된다.**

| 기존 장치 | λ 융합에서의 지위 |
|---|---|
| ① 공간 backoff 후보생성 | λ=1 특수해 |
| ③ tie 게이팅 (`f_min=0.5`) | λ→0 극한. 손으로 고른 하이퍼파라미터 **제거** |
| ② 타입조건부 가우시안 | 직교. ablation 항목으로만 유지 |
| σ 자동 게이팅 (관계 축) | 직교. 그대로 유지 |

세 heuristic이 하나의 식으로 줄고 하이퍼파라미터가 하나 사라진다. 기여문이
"공간 재순위화를 제안한다"에서 **"시간 규칙의 불확실성이 공간 근거의 발언권을
정한다"** 로 올라간다.

기존 σ 자동 게이팅은 *"이 관계에 공간이 의미 있는가"*(관계 축)이고 λ는 *"이
쿼리에 시간이 이미 답을 아는가"*(쿼리 축)다. 직교하는 두 축 모두 자동이므로
"어디에 공간을 쓸지 사람이 지정하지 않는다"는 설계적 novelty가 강화된다.

### 3.3 공간 적합도의 폴백 계층

`S_S(c)`는 규칙별 가우시안을 우선 쓰고, 규칙이 없거나(λ=1) 해당 특징이
미학습이면 관계 수준 가우시안(`fit_relation_spatial`)으로 내려간다. 둘 다 없으면
`S_S = 1`이 되어 식이 자동으로 TLogic으로 환원된다.

특징집합은 기존 (d, Δd, cos β)를 유지한다. 방향성 불변량 확장은 이번 범위에서
제외한다.

### 3.4 회귀 보증

`λ ≡ 0` 강제 시 순정 TLogic 수치와 비트 단위로 일치해야 한다. 백마고지에서
`--spatial off`로 썼던 것과 같은 안전장치다.

### 3.5 CLI

기존 `--spatial` / `--type_cond` / `--fmin`은 ablation용으로 유지하고 다음을
추가한다. `--backoff`는 폐기한다(λ=1로 흡수).

```
--fusion {fixed, fmin, lambda}    기본 lambda
--tau <float>                     λ' = λ^τ, 기본 1.0 (무튜닝)
```

## 4. 실험 설계

### 4.1 프로토콜

- 쿼리: TLogic 표준대로 양방향(`(s,r,?,t)` + 역관계). 후보공간 = 전체 엔티티.
- 지표: MRR, Hits@1/3/10 (time-aware filtered).
- 타겟 엣지 ≥10,000 기준 test ≈1,000 쿼리 ×2방향 = 2,000. ICEWS14(7,371)보다
  작으므로 다중 seed 분산 보고를 필수로 한다.

### 4.2 데이터셋 타당성 게이트 (사전 등록)

모든 실험에 앞서 통과해야 한다.

```
무학습 베이스라인(recency, frequency) MRR  <  TLogic MRR − 0.10
```

깨지면 방법론이 아니라 **데이터셋을 다시 만든다.** §1.2를 절차로 고정한 것이다.

### 4.3 핵심 표 — 확장 유/무 × 방법

(결과 기입용 서식)

| | 확장 **없음** | 확장 **있음** |
|---|---|---|
| recency / frequency (무학습) | — | — |
| 최근접 적 (기하 단독) | — | — |
| **TLogic** | — | — |
| **STLogic (λ)** | — | — |
| **격차 Δ** | **> 0 이어야 함** | **> 0 이어야 함** |

두 열 모두에서 Δ>0이어야 일반화가 입증된다. 타겟 집합이 동일하므로 숫자가 직접
비교된다.

### 4.4 Ablation 사다리

**(a) 특징 축** — 기존 유지
`off` → `dist` → `dist+Δd` → `dist+Δd+cosβ` → *(대조군)* `+절대좌표`

**(b) 융합 축** — 신규, 이번 기여의 핵심
`고정가중` → `f_min 게이팅(백마고지 방식)` → **`λ 적응`**

**(c) λ 구간 분해** — 이득의 귀속

| 구간 | 의미 | 백마고지 대응 |
|---|---|---|
| λ=1 | 규칙 미발화 | ① backoff |
| 0<λ<1 | 후보 경합 | 재순위화 |
| λ=0 | 규칙 단정 | 무개입(보호) |

**(d) 필수 대조군** — 비-공간 backoff(빈도/랜덤)를 λ=1 구간에 투입한다. 이득이
"빈칸을 채워서"가 아니라 **"공간이라서"** 임을 증명한다. 이것이 없으면 백마고지
최대 성과(+4.3%p)의 귀인이 무너진다. PROGRESS §6-2에서 이미 지적된 항목이다.

### 4.5 진영 홀드아웃 (보조, inductive 주장)

FR 주체 학습 → EN 주체 예측. 두 가지가 무너져야 한다.

- **절대좌표 대조군** 붕괴 → frame-invariance가 원리적 요구임을 실증
- **임베딩 모델** 붕괴 → STLogic의 차별점

메인이 transductive이므로 RE-Net·CyGNet·TiRGN·STSE가 **실행 가능해진다.**
PROGRESS §6-0(나)의 프로토콜 블로커는 데이터셋 교체로 자동 해소됐다.

### 4.6 비교군 우선순위

| 순위 | 대상 | 비고 |
|---|---|---|
| 1 | TLogic, recency, frequency, 최근접 적 | 필수·즉시. 무학습 3종은 신뢰 확보용으로 반드시 표에 넣는다 |
| 2 | CounTRuCoLa | 규칙 기반. TGB 2.0 커스텀 변환 필요 |
| 3 | RE-Net / CyGNet / TiRGN | `nec-research/TKG-Forecasting-Evaluation` 통합 프레임, GPU |
| 4 | STSE | 좌표 입력 STKG 임베딩. 가장 가까운 경쟁자 |

### 4.7 엄밀성

- **다중 seed ≥5**, 평균±표준편차. 백마고지는 seed=12 단일이었다.
- **λ 분포 히스토그램**을 두 데이터셋에 대해 보고 → "체제가 다르다"의 정량적
  근거이자 이 방법의 존재 이유.
- §2.4 합격검사 수치를 데이터셋 절에 공개.
- Case study: 동일 규칙이 만든 다수 후보에서 λ가 개입해 정답이 올라간 실사례.

### 4.8 성공 기준 (사전 등록)

```
STLogic − TLogic  MRR 격차 ≥ +2%p,  확장 유/무 양쪽,  5 seed 표준편차 비중첩
```

**격차가 지나치게 클 경우(+20%p 이상) 순환 유출을 의심하고 §2.4 합격검사부터
재감사한다.** 큰 격차는 좋은 소식이 아닐 수 있다.

## 6. 위험과 대비

**(가) λ가 전부 0으로 몰려 아무 일도 일어나지 않는다.** VR-Forces는 반복성이
높아 규칙이 자신 있게 발화할 수 있다. 백마고지에서 재순위화가 +0.4%p에 그친 것과
같은 실패 양상이다.
→ λ 분포를 진단 지표로 보고한다. 0 쪽에 몰리면 온도 τ를 valid에서 튜닝하되,
"하이퍼파라미터 0개"를 포기했음을 명시하고 τ=1 결과를 반드시 병기한다.
§2.2의 증량 요건(사수당 표적 ≥3)이 지켜지면 λ가 중간 구간에 분포하게 되어 있다 —
**데이터 요건과 방법 요건이 같은 것을 요구한다.**

**(나) 증량 데이터가 합격검사를 통과하지 못한다.**
→ 방침을 고쳐 재생성한다. 반복 실패 시 LLM이 시나리오 원문을 증보하고 기존
파이프라인(02→04)을 태워 VR-Forces를 재실행하는 방식으로 올린다. 정답 사건을
시뮬레이터가 생성하므로 과학적으로 더 강하나 수동 GUI 실행 비용이 든다.

**(다) test 쿼리 2,000건은 작다.** 다중 seed와 신뢰구간으로 보완하고 규모의
한계를 논문에 명시한다.

**(라) 합성 타겟에 대한 리뷰어 반발.** §2.3의 방침 파일 공개, §2.4 합격검사 수치
공개, 실제 시뮬레이션 유래 4쌍 부분집합의 별도 보고로 대응한다.
