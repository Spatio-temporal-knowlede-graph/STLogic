# battlefield hill395 large

## Experimental setup

### *Dataset*

- 자체 구축한 백마고지 전장 시공간 지식 그래프(battlefield_hill395) 데이터셋을 이용하여 수행
    
    [‣](https://app.notion.com/p/37ade7c5378c80a0a790e19fecb5ba05?pvs=21) 
    
    https://github.com/dbstj589/CITA-Net
    
    - 1,005,101 트리플과 75개의 섹터로 구성되며, 각 섹터는 서로 다른 전장 상황의 시간별 관측을 담음
    - 75개 섹터는 학습 50 / 검증 12 / 테스트 13 으로 사전 분할되어 있음
    - 원천 STKG를 규칙 학습 입력 형식(head, relation, tail, timestamp, location의 5컬럼)으로 변환함
        - location 컬럼은 STLogic의 공간 모델만 사용하며, baseline TLogic은 앞 4컬럼만 읽으므로 두 모델 모두 동일 파일을 공유함
        - fact는 각 섹터 observations.jsonl의 relations[]에서만 생성했고, landmark 좌표만 stkg.nt에서 보강함
        - 다중 객체 융합 정답 파일과 미매칭 관측 파일은 사용하지 않아, 매칭된 실체가 두 노드로 병존하는 미융합 멀티소스 상태로 학습 및 평가를 진행함
    - 또한, 원천 STKG는 섹터별로 엔티티 id를 독립 부여하여 섹터 네임스페이싱으로 분리함

### *Evaluation metric*

- MRR
    - 정답이 얼마나 높은 순위에 배치되는지를 전체적으로 평가함
- Hits@1, Hits@3, Hits@10
    - 정답이 상위 N개 안에 포함된 비율

## *STLogic: 1차 실험*

[1차 실험 자세히 보기 (1)](https://app.notion.com/p/1-1-3a495b3368698080bb63c199c34d1b29?pvs=21)

- 공간 정보를 이용한 후보 재순위화
    - 기존 TLogic이 시간 규칙을 이용하여 후보를 만들면, STLogic은 이 각 후보의 공간적 타당성을 계산해 순위를 다시 조정하는 것
- ***1차 ablation - 재순위화의 효과 측정***
    - 공간 특징을 계층적으로 활용하여 기존 후보의 재순위화 효과를 측정함
    
    | 구성 | MRR | Hits@1 | Hits@3 | Hits@10 |
    | --- | --- | --- | --- | --- |
    | off (=baseline) | 0.5464 | **0.5156** | 0.5482 | 0.6117 |
    | dist only | **0.5467** | 0.5122 | **0.5505** | **0.6285** |
    | dist+Δd | 0.5443 | 0.5117 | 0.5466 | 0.6167 |
    | dist+Δd+β | 0.5457 | 0.5135 | 0.5481 | 0.6172 |
- ***1차 진단***
    - 규칙 σ가 과대해 변별력이 약함
    - TLogic이 후보를 생성한 쿼리에서는 이미 정답을 1위에 놓는 경우가 많았음
        - 즉, 이미 정답이 1위라면 공간 정보를 추가해도 더 좋아질 수 없음 (=ceiling effect, 천장 효과)
        - 전체 쿼리 중 TLogic이 답을 생성할 수 있었던 쿼리에서는 약 72.5%가 이미 정답 1위였음
        - 따라서 전체 평균 MRR만 보면 공간 재순위화의 효과가 작게 나타남
    - 하지만 TLogic이 정답을 1위로 놓지 못한 어려운 쿼리만 따로 분석하였더니 결과가 달랐음
        - 즉, 공간 정보는 실제로 작동하고 있음을 확인함
        - 다만 전체 쿼리 중 상당수는 이미 정답이 1위였기 때문에 그 효과가 평균에 묻힌 것임

## *STLogic: 2차 실험*

[2차 실험 자세히 보기 (1)](https://app.notion.com/p/2-1-3a495b33686980bcaca7cde673a1e5df?pvs=21)

- 1차 진단 후, 공간 정보가 불필요한 경우 기존 TLogic의 정답 순위를 오히려 떨어뜨릴 가능성을 줄이기 위해 두 가지 보조 실험을 진행함
    - **첫 번째, 타입 조건부 공간 적용**
        - 모든 후보에 똑같이 공간 점수를 적용하는 것이 아니라, 후보의 유형이나 관계 유형을 고려하여 더 적절한 후보끼리 고려하는 방법임
        - 예를 들어, 다음과 같은 후보들이 섞여 있을 경우
            
            ```jsx
            백마고지: 지형
            보병대대: 부대
            전차 1: 개별 객체
            ```
            
            서로 성격이 다른 후보를 동일한 거리 기준으로 비교하면 공간 점수가 왜곡될 수 있으므로 타입을 고려하는 조건을 추가함
            
    - **두 번째, Tie-gating**
        - 공간 정보를 항상 강하게 적용하지 않고, 기존 TLogic 후보 점수가 서로 비슷할 때만 공간 정보를 사용하는 방식임
            
            예를 들어, TLogic 점수가 다음과 같다면 공간 정보를 적극적으로 사용함
            
            ```jsx
            후보 A: 0.75
            후보 B: 0.75
            후보 C: 0.75
            
            -> 후보 간 시간 점수 차이가 거의 없으므로 공간 정보가 순위를 구분하는 데 유용함
            ```
            
            반면 다음과 같다면 TLogic의 강한 판단을 유지함
            
            ```jsx
            후보 A: 0.95
            후보 B: 0.40
            후보 C: 0.20
            
            -> 이 경우 공간 정보 때문에 정답 후보 A가 밀려나는 것을 방지함
            ```
            
- ***2차  결과***
    
    
    | 구성 | MRR | Hits@1 | Hits@3 | Hits@10 |
    | --- | --- | --- | --- | --- |
    | dist only | 0.5467 | 0.5122 | 0.5505 | 0.6285 |
    | dist + type | 0.5466 | 0.5118 | 0.5504 | 0.6290 |
    | dist + gate | 0.5487 | 0.5144 | 0.5537 | 0.6279 |
    | dist + type + gate | **0.5502** | **0.5151** | **0.5559** | **0.6308** |
- ***2차 진단***
    - 재순위화는 이미 천장에 근접함
    - 또한, 테스트 쿼리 중 11,118건에서는 TLogic 규칙이 전혀 발화되지 않음 → 재순위화는 이미 존재하는 후보의 순서만 바꾸는 기능하기 때문에 이러한 쿼리는 재순위화로 개선할 수 없음
    - 따라서 성능을 크게 높이기 위해서는 기존 후보를 조금 더 잘 정렬하는 것보다, **후보가 없는 쿼리에 새로운 후보를 만들어 주어야 한다**는 결론을 내림

## *STLogic: 3, 4차 실험*

[3, 4차 실험 자세히 보기 (1)](https://app.notion.com/p/3-4-1-3a495b336869809c93bffdedf2803ab2?pvs=21)

- ***공간 backoff***
    - 공간 backoff는 시간 규칙이 발화되지 않은 경우에만 작동함
        - 1차: TLogic 시간 규칙으로 후보 생성 시도
        - 2차: 후보가 없으면 공간 패턴으로 후보 생성
        
        ```jsx
        ex) **moveToward** 관계가 학습 데이터에서 일반적으로 다음 공간 특성을 보였다고 가정할 때,
        - subject와 object 거리가 비교적 가까움
        - 시간이 지나면서 거리가 감소함
        
        테스트 시점에서 시간 규칙은 발화하지 않았지만, 다음 후보들이 존재할 수 있음
        - 후보 A: 거리 400m, 접근 중
        - 후보 B: 거리 2,500m, 멀어지는 중
        - 후보 C: 거리 600m, 접근 중
        
        STLogic은 관계별 공간 분포와 비교하여 A와 C를 후보로 생성함
        ```
        
    - 즉, 후보를 재정렬하는 것이 아니라 후보 자체를 새로 생성함
- ***3차 진단***
    - 공간 정보의 더 큰 역할은 후보의 순서를 바꾸는 것이 아닌 시간 규칙이 실패할 경우 새로운 후보를 생성하는 데 있음
    - 공간 backoff를 적용했음에도 8,987건에서 후보가 생성되지 않았음
    - 이를 다시 관계별로 분석해 본 결과, 남은 쿼리의 약 98.9%가 다음 관계에 집중되어 있었음
        
        ```jsx
        partOf
        supports
        reinforces
        ```
        
        - 위 관계들의 공통점은 대상이 개별 전차나 병사가 아닌 부대 엔티티라는 것임
        - 개별 객체에는 좌표가 있으나 대대나 연대 같은 부대 엔티티에는 직접적인 좌표가 없었음
    - 공간 backoff는 두 엔티티 사이의 거리 등을 계산해야 하므로, 대상 부대의 좌표가 없으면 후보 점수를 계산할 수 없음
    - 즉, 남은 no-candidate의 원인은 공간 모델의 성능 부족이 아닌 **부대 위치가 정의되어 있지 않다는 데이터 표현 문제**였음

### *STLogic: 4차 실험*

- ***부대 중심점 확장***
    - 부대에는 직접적인 좌표가 없지만, 부대에 소속된 구성원들은 좌표를 지니고 있음
    - 따라서 구성원들의 위치 평균을 부대의 대표 위치로 사용함
        
        ```jsx
        예를 들어 제1대대의 구성원이 다음 위치에 있다고 가정함
        - 전차 1: (100, 200)
        - 전차 2: (120, 200)
        - 전차 3: (110, 210)
        
        부대 중심점은 다음과 같이 계산할 수 있음
        - 제1대대 중심정: (110, 210)
        
        부대가 상위 부대에 속한 경우에는 계층적으로 계산함
        병사/전차 위치 -> 중대 중심점 -> 대대 중심점 -> 연대 중심점
        
        이렇게 하면 다음 관계에도 공간 backoff를 적용할 수 있음
        
        전차 partOf 대대
        포병 supports 대대
        대대 reinforces 연대
        ```
        
- ***3, 4차 결과***
    - no-candidate: 8,987건 → 3,146건
    
    | 구성 | MRR | Hits@1 | Hits@3 | Hits@10 |
    | --- | --- | --- | --- | --- |
    | dist + type + gate | 0.5502 | 0.5151 | 0.5559 | 0.6308 |
    | backoff only
    (backoff + 부대 중심점) | 0.5856 | 0.5256 | 0.5880 | 0.7368 |
    | dist + type + gate + backoff | **0.5891** | **0.5286** | **0.5933** | **0.7390** |
- ***4차 진단***
    - 남아있는 3,146건은 주로 supports, reinforces 관계이며 대상이 연대급 부대임
    - 현재 변환 데이터에는 다음과 같은 하위 계층이 충분히 들어 있음
        - 개별 객체 → 소대
        - 소대 → 중대
        - 중대 → 대대
    - 하지만 대대 → 연대 정보가 누락되어 있음
    - 따라서 연대의 구성원을 추적할 수 없고, 연대 중심점도 계산할 수 없음
        - 향후 대대 - 연대 계층을 추가하면 남은 후보 없음 쿼리도 일부 더 줄일 수 있음

## *STLogic: 1차 실험*

- 공간 정보를 이용한 후보 재순위화
    - temporal random walk를 통해 시간 규칙을 생성하고, 이를 이용해 후보를 만들면 STLogic은 각 후보의 공간적 타당성을 계산해 순위를 재조정함
    - 객체 간 거리, 거리 변화량, 상대 방위를 이용해 규칙 별 평균 및 표준편차 모델링함

| 구성 | MRR | Hits@1 | Hits@3 | Hits@10 |
| --- | --- | --- | --- | --- |
| off (=baseline) | 0.5464 | **0.5156** | 0.5482 | 0.6117 |
| dist only | **0.5467** | 0.5122 | **0.5505** | **0.6285** |
| dist+Δd | 0.5443 | 0.5117 | 0.5466 | 0.6167 |
| dist+Δd+β | 0.5457 | 0.5135 | 0.5481 | 0.6172 |
- 규칙의 표준편차가 과대해 변별력이 약해짐
- TLogic이 후보를 생성한 쿼리에서는 이미 정답을 1위에 놓는 경우가 많음
    - 즉, 이미 정답이 1위라면 공간 정보를 추가해도 더 좋아질 수 없음 (=ceiling effect, 천장 효과)
    - 전체 쿼리 중 TLogic이 답을 생성할 수 있었던 쿼리에서는 약 72.5%가 이미 정답 1위였음
    - 따라서 전체 평균 MRR만 보면 공간 재순위화의 효과가 작게 나타남
- 하지만 TLogic이 정답을 1위로 놓지 못한 어려운 쿼리만 따로 분석하였더니 결과가 달랐음
    - 즉, 공간 정보는 실제로 효과가 있었음을 확인함
    - 다만 전체 쿼리 중 상당수는 이미 정답이 1위였기 때문에 그 효과가 평균에 묻힌 것임

## *STLogic: 2차 실험*

- 1차 실험 후, 공간 정보가 불필요한 경우에는 기존 TLogic의 정답 순위를 오히려 떨어뜨릴 가능성이 있으므로 이를 줄이기 위해 두 가지 보조 실험을 진행함
    - 첫 번째, 대상 타입별로 분포를 따로 적용
        - 대상 타입별(부대, 개별 객체 등)로 평균 및 분포를 따로 적용하여 변별력을 상승시키고자 함
    - 두 번째, TLogic 점수가 비슷한 후보들에게만 공간 정보 사용
        - 기존 TLogic 후보 점수가 서로 비슷할 때만 공간 정보를 적극적으로 사용하고자 함

| 구성 | MRR | Hits@1 | Hits@3 | Hits@10 |
| --- | --- | --- | --- | --- |
| off (=baseline) | 0.5464 | **0.5156** | 0.5482 | 0.6117 |
| dist only | 0.5467 | 0.5122 | 0.5505 | 0.6285 |
| dist + type | 0.5466 | 0.5118 | 0.5504 | 0.6290 |
| dist + gate | 0.5487 | 0.5144 | 0.5537 | 0.6279 |
| dist + type + gate | **0.5502** | 0.5151 | **0.5559** | **0.6308** |
- 재순위화는 이미 천장에 근접하므로 높은 성능 향상을 볼 수 없음
- 테스트 쿼리 중 11,118건에서는 TLogic 규칙이 전혀 발화되지 않음을 확인함
    - 재순위화는 이미 존재하는 후보의 순서만 바꾸는 기능을 하기 때문에 이러한 쿼리는 재순위화로 개선할 수 없음
- 따라서 성능을 크게 높이기 위해서는 기존 후보를 조금 더 잘 정렬하는 방식 보다 후보가 없는 쿼리에 새로운 후보를 만들어 주어야 한다는 결론을 내림

## *STLogic: 3차 실험*

- 1,2차 실험을 통해 다음과 같은 사실을 발견함
    - 규칙이 발화한 쿼리는 이미 정답 rank-1이 72.5%이며, 2차의 최선이 +0.38%임
    - 반면 test 쿼리는 20,210건 중 11,118건은 규칙이 아예 발화되지 않아 후보가 0개임
    - 즉, 잘 맞힌 것을 더 잘 맞히는 것이 아닌 못 맞히던 걸 살리기에 초점을 두어야 함
- 3차 실험은 규칙이 없는 쿼리에 대해 공간 정보만으로 후보를 새로 만들어내고자 함
    - backoff 방식: 시간 규칙이 발화되지 않은 쿼리에 대해 공간적으로 적합한 후보 생성
        - 1차로 TLogic 시간 규칙을 이용해 후보 생성을 시도하고
        - 2차로 후보가 없으면 공간 패턴으로 후보를 생성함
- 하지만 3차 실험 중 여전히 no candidate가 8,987건이 남아있음을 발견함
    - 부대 중심점 방식: 사용하는 데이터셋에서 부대의 직접적인 좌표가 없으므로 부대 소속 구성원들의 좌표를 이용해 중심점을 구하고, 이를 부대 대표 위치로 사용함

| 구성 | MRR | Hits@1 | Hits@3 | Hits@10 |
| --- | --- | --- | --- | --- |
| off (=baseline) | 0.5464 | 0.5156 | 0.5482 | 0.6117 |
| dist + type + gate | 0.5502 | 0.5151 | 0.5559 | 0.6308 |
| backoff only
(backoff + 부대 중심점) | 0.5856 | 0.5256 | 0.5880 | 0.7368 |
| dist + type + gate + backoff | **0.5891** | **0.5286** | **0.5933** | **0.7390** |
| ㄴ (baseline 대비 성능 향상(%)) | **+7.81%** | **+2.52%** | **+8.23%** | **+20.81%** |
- 여전히 3,146건의 no-candidate가 남았으나, 이는 대대 → 연대 정보가 누락되어 생긴 문제이므로 데이터상에서의 보완이 필요함
    - 현재 데이터에는 다음과 같은 하위 계층이 충분히 들어가 있음
        - 개별 객체 → 소대
        - 소대 → 중대
        - 중대 → 대대
